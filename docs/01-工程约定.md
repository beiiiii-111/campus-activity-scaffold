# 工程约定

## 1. 目录与端口

```
campus-activity-tutorial/
├── server/    Spring Boot 4.1.2 后端，固定 8016
├── app/       uni-app + Vue3 + TS 学生端，type-check 为检查项，H5 预览 5174
├── admin/     Vite + Vue3 + TS 管理后台，固定 5173
└── docs/      工程约定、接口约定、问题记录、提交报告
```

端口来源：作业明确要求后端 8016、后台 5173、小程序可 type-check。三个端口写死后不再改动，
避免出现"服务起在别的端口、截图对不上"的情况。

## 2. 提交规范（Conventional Commits）

格式：`<type>(<scope>): <subject>`

| 字段 | 取值 |
| --- | --- |
| type | `feat` 新功能 / `fix` 修复 / `chore` 工程配置 / `docs` 文档 / `test` 测试 / `refactor` 重构 |
| scope | `shared` 仓库级 / `server` 后端 / `app` 学生端 / `admin` 管理后台 |
| subject | 中文，一句话说清这一步做了什么，不加句号 |

约束：

- 一步一件事，一个提交能在几分钟内讲清楚；不把三端混在一个提交里。
- 提交前必须保证该端能跑：后端能起、前端能 `type-check`。
- 提交顺序即实现顺序，便于对照检查点逐条验收。

## 3. 分支

- `main` 为主干，七个脚手架提交直接落 `main`，与作业给出的顺序一一对应。
- 本地提交完成后推送 `origin/main`，报告里的"远程分支"指向该分支。

## 4. 代码风格

- Java：包根 `top.yixz.activity`，按 `common / config / controller / dto / service / vo` 分层；
  统一用 record 承载不可变数据结构，Lombok 只用于日志与 getter。
- TypeScript：`strict: true`，禁止 `any` 兜底；接口出入参类型集中在 `types` 单文件里，前后端字段同名同义。
- 注释写"为什么"，不写"是什么"；错误分支必须有中文提示语。
