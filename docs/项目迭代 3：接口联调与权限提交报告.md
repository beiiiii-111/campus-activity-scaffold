### 5.3 上传格式不支持（前端拦截 + 后端 70003 兜底）

权限做了四层，从弱到强，越权在第三层就被挡住，即使绕过前端还有第四层。

| `admin` | ADMIN | `Admin@123` | 全部 5 个菜单 |

### 6.2 四层收口

| 层 | 位置 | 做法 |
| --- | --- | --- |
| 菜单级 | `admin/src/layout/index.vue` | `allMenus` 每项带 `roles`，`computed` 按当前角色过滤 |
| 路由级 | `admin/src/router/index.ts` | `/user`、`/log` 的 `meta.roles: ['ADMIN']`，守卫不匹配直接 `return { path: '/403' }` |
| 按钮级 | `admin/src/directives/permission.ts` | `v-perm="['ADMIN']"`，角色不符就把节点摘掉（活动管理「下架」、用户管理「设置角色」） |
| 接口级 | 后端 `SecurityConfig` + `@PreAuthorize` | `/api/admin/**` 只放 `REVIEWER/ADMIN`；`AdminUserController` 再收紧到 `ADMIN` |

关键代码（`admin/src/directives/permission.ts`）：

```ts
const permission: Directive<HTMLElement, string[] | string> = {
  mounted(el, binding) {
    const store = useUserStore()
    if (!canAccess(binding, store.role)) el.parentNode?.removeChild(el)
  }
}
```

小程序端同理：学生 token 请求 `/api/org/**` 被后端 403（`code 10002`），工作台不弹 toast 了事，而是整屏显示「没有组织者权限」。

## 七、问题记录（现象 → 排查 → 原因 → 解决 → 预防）

### 问题 1：操作日志页 `createTime` 显示成 `2026-11-24T12:55:48`

- **现象**：表格「时间」列每一行都带个 `T`，和页面其他时间列风格不一致。
- **排查**：`curl` 打接口看原始响应，`createTime` 就是 ISO 格式；再看 `application.yml` 里配的 `spring.jackson.date-format: yyyy-MM-dd HH:mm:ss`。
- **原因**：`date-format` 只对 `java.util.Date` 生效，实体字段是 `LocalDateTime`，走的是 JSR-310 序列化，输出 ISO。
- **解决**：前端 `formatTime()` 把 `T` 替换成空格（最小改动，不动后端）。
- **预防**：接口文档里注明「`LocalDateTime` 字段返回 ISO 串」，前端时间列一律走 formatter，不直接绑字段。

### 问题 2：分页显示「共 8 条」但页码是灰的

- **现象**：日志页 8 条数据，`el-pagination` 只有总数，没有可点的页码。
- **排查**：Network 看响应 `"total":"8"`（带引号）；`el-pagination` 的 `total` 要 number。
- **原因**：后端为防 JS 精度丢失，把 `Long` 统一序列化成字符串，`PageResult.total` 也跟着变成字符串。
- **解决**：`total.value = Number(data.total)`。
- **预防**：类型注释写明「Long 一律字符串」，所有数字字段读进来先 `Number()`。

### 问题 3：上传后的封面在 H5 显示裂图

- **现象**：上传成功，toast 也提示成功，但 `<image>` 是裂的。
- **排查**：`curl http://127.0.0.1:5174/uploads/xxx.png` → **404**；`curl http://127.0.0.1:8016/uploads/xxx.png` → **200**。
- **原因**：`vite.config.ts` 只代理了 `/api`，`/uploads/**` 被当成前端静态目录找了。
- **解决**：补一段 `'/uploads'` 代理到 8016，复测 200。
- **预防**：凡是后端直接吐的静态路径（`/uploads`、`/files`），联调第一天就加进代理。

### 问题 4：学生 token 打开组织者工作台，页面只剩空壳

- **现象**：学生手输 `#/pages/org/workbench`，概览全 0、列表空，只弹了一个「没有操作权限」的 toast。
- **排查**：Network 里 `/api/org/dashboard` 是 403，body `{"code":10002}`；页面 `catch` 里只 `console`，没处理。
- **原因**：请求层把 403 当普通错误抛出，页面没有对应分支。
- **解决**：工作台 `catch` 里判断 `code === 10002 || status === 403` → 整屏「没有组织者权限」+ 返回按钮；请求层把 `code` 带进 `ApiError`。
- **预防**：每加一个受权限保护的页面，先想「无权限时长什么样」，并在自测清单里留一条。

### 问题 5：新页面 `#/pages/checkin/scan` 一直 404

- **现象**：`pages.json` 里加了路径，重启前访问还是渲染首页。
- **排查**：`pages.json` 改动后 dev server 只热更新样式，路由表不重建。
- **原因**：uni-app 的页面路由在 dev server 启动时由 `pages.json` 生成。
- **解决**：停掉 `npm run dev:h5` 重启，新页面立刻可达。
- **预防**：动 `pages.json` 的提交，验证前必须重启 dev server（这条上一轮踩过，这轮又踩了一次，已写进自测清单）。

## 八、AI 协作记录

### 第 1 次：把 Network 的 403 响应原样丢给 AI 排障（指定动作）

- **我提问**：把 `/api/admin/users` 的 Network 请求整条贴过去——Request URL、Status 403、Response `{"code":10002,"message":"没有操作权限"}`，问「前端已经隐藏了菜单，为什么还能发出这个请求，是不是后端配置错了？」
- **AI 判断**：不是配置错，是**两套权限在同时生效**：`SecurityConfig` 的 `/api/admin/**` 只放 `REVIEWER/ADMIN`，而 `AdminUserController` 又用 `@PreAuthorize("hasAnyRole('ADMIN')")` 收紧；`reviewer01` 能登录（`adminLogin` 只拦非 REVIEWER/ADMIN），但调用户接口必然 403。
- **哪条建议有效**：AI 指出「403 是 Spring Security 的 `AccessDeniedHandler` 回的，不是 `@PreAuthorize`」——我去看 `JsonAccessDeniedHandler` 确认了 body 结构和日志位置，据此把结论写成「越权在接口层被拦，返回统一 JSON」，第五、六节的截图说明就是按这个写的。
- **采纳结果**：确认不用改后端；前端把 `/log`、`/user` 的 `meta.roles` 收紧到 `ADMIN`，与后端口径对齐。

### 第 2 次：错误码要不要在请求层统一转成中文

- **我提问**：签到有 5 个错误码，全部在请求层 `switch` 转成文案行不行？
- **AI 建议**：请求层只管 toast 兜底，**差异化引导放页面**，因为同一错误码在不同页面下一步不一样（40002 在签到页要引导「去我的报名」，在报名页要引导「重新报名」）。
- **我的判断**：部分采纳。请求层改成「带出 code + 统一 toast」，错误卡与跳转按钮放在页面里，`ERROR_MAP` 只声明文案与动作。
- **结果**：签到页的错误卡能按码给出不同建议，其他页面不受影响。

### 第 3 次：签到码做成一次性还是时间段轮换

- **我提问**：签到码用一次就失效是不是更安全？
- **AI 建议**：一次性，用完即删。
- **我的判断**：**否决**。现场几十人同时扫，一次性码会让后扫的人全部失败；后端已实现「时间片 + 容错 N 片」的 TOTP 思路（`CheckinTokenService`），保留 30 秒轮换更符合场景。
- **结果**：核销台按 `refreshSeconds` 自动刷新，跨片扫码也能过；代价是有人拍照转发也能签，属可接受的现场风险。
