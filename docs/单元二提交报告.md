## 二、复现说明（约 460 字）

**组件拆分思路**：按「一屏一职责」切，先切页面骨架再切重复块。后台把「标题条 + 状态标签 + 空状态 + 列表工具条 + 详情抽屉」抽成 5 个组件，判断标准是**同一段结构在第二个页面出现第二次就抽**，所以 5 个组件全部被 2 处以上复用（PageHeader 和 EmptyState 各 4 处）。组件只负责展示与事件上抛，取数、分页、弹窗确认留在页面里，避免组件持有业务状态。小程序同理抽出 ActivityCard、SectionTitle、EmptyState，首页与列表页共用卡片，改一次样式两端同时生效。

**路由表设计**：后台用「公共路由 + 布局路由 + 兜底路由」三层。`/login`、`/403`、`/404` 标 `meta.public`；业务页全部挂在 `/` 这个布局路由的 children 下，Layout 只负责侧边栏与顶栏，页面切换不重挂外壳；最后 `/:pathMatch(.*)*` 统一送 404。每条业务路由用 `meta.roles: ['ADMIN']` 标注角色要求，守卫在 `router.beforeEach` 里读 `to.meta`：未登录跳登录并带 `redirect` 参数，登录后原路返回；角色不匹配跳 403；已登录再去登录页直接送回首页。

**状态分层思路**：分三层——① 组件内部的 UI 状态（弹窗开关、加载中）就地 `ref`；② 跨页共享的登录态放 Pinia（`stores/user.ts`），token 与用户信息同时写内存与持久层；③ 服务端数据不缓存，每次进页面按需请求，避免「列表改了但详情还是旧的」。持久层后台用 `localStorage`、小程序用 `uni.setStorageSync`，store 初始化时反读，所以刷新浏览器或重启小程序都保持登录；登出时内存与持久层一起清，不会刷新后「复活」。

## 四、路由表

文件：`admin/src/router/index.ts`，守卫在 **第 76 行** `router.beforeEach`（登录校验 + 角色校验），公共路由以 `meta.public = true` 放行。

| 路径 | 名称 | 组件 | 角色要求 | 守卫行为 |
| --- | --- | --- | --- | --- |
| `/login` | Login | `views/login/index.vue` | `public`（免登录） | 已登录访问 → 重定向 `/` |
| `/403` | Forbidden | `views/error/403.vue` | `public` | — |
| `/404` | NotFound | `views/error/404.vue` | `public` | — |
| `/` | —（布局路由） | `layout/index.vue` | 需登录 | `redirect: /dashboard` |
| `/dashboard` | Dashboard | `views/dashboard/index.vue` | `meta.roles: ['ADMIN']` | 未登录 → `/login?redirect=…`；角色不符 → `/403` |
| `/audit` | Audit | `views/audit/index.vue` | `meta.roles: ['ADMIN']` | 同上 |
| `/activity` | Activity | `views/activity/index.vue` | `meta.roles: ['ADMIN']` | 同上 |
| `/user` | User | `views/user/index.vue` | `meta.roles: ['ADMIN']` | 同上 |
| `/:pathMatch(.*)*` | — | — | — | `redirect: /404` |

守卫逻辑（`router/index.ts:76` 起）：

```ts
router.beforeEach((to) => {
    const userStore = useUserStore()
    if (to.meta.public) { /* 已登录去登录页 → 回首页 */ return true }
    if (!userStore.isLogin) return { path: '/login', query: { redirect: to.fullPath } }
    const roles = to.meta.roles as string[] | undefined
    if (roles?.length && !roles.includes(userStore.role)) return { path: '/403' }
    return true
})
```

## 六、问题记录

### 问题 1：新增页面后路由 404，页面一直回首页

- **现象**：`pages.json` 里加了 `pages/activity/list` 后，访问 `#/pages/activity/list` 仍然渲染首页；改成 750 宽截图也是首页。
- **原因**：uni-app 的页面路由表是在 dev server 启动时由 `pages.json` 生成的，运行中改 `pages.json` 只触发了样式热更新，路由表没重建。
- **解决**：停掉 `npx uni` 重新启动，新页面立刻可达。
- **预防**：凡是动 `pages.json`（新增页面、改 tabBar）的提交，验证前先重启 dev server。

### 问题 2：分页显示「共 8 条」但页码是灰色、翻页无效

- **现象**：用户管理页表格有 8 条数据，`el-pagination` 却显示不出页码。
- **原因**：后端把 `Long` 序列化成字符串避免 JS 精度丢失，`PageResult.total` 实际是 `"8"` 而不是 `8`；`el-pagination` 的 `total` 要求 number，拿到字符串后内部比较失效。
- **解决**：三个列表页统一 `total.value = Number(data.total)`。
- **预防**：接口类型注释里写明「后端 Long 一律序列化为字符串」，所有数字字段读进来先转 `Number()`，不要直接绑给组件。

### 问题 3：Vue 模板里写 TypeScript 非空断言 `current!` 报编译错误

- **现象**：审核页抽屉底部按钮写 `@click="approve(current!)"`，`vue-tsc` 直接报错。
- **原因**：模板表达式不是 TS 上下文，`!` 后缀断言不合法（只有 `script` 块里可用）。
- **解决**：包一层方法 `approveCurrent()` / `rejectCurrent()`，在脚本里做空值判断。
- **预防**：模板只写简单表达式，判空、断言统一放 `script`，也让模板更好读。

### 问题 4：连续测试两个手机号，第二个验证码收不到

- **现象**：第一个手机号登录正常，换第二个号点「获取验证码」，验证码框空着、登录按钮灰着。
- **原因**：后端 `send-interval-seconds: 60` 有 60 秒频控，同一 IP 内重复发送返回业务错误，`mockCode` 不会回传。
- **解决**：测试时换未发送过的手机号，或等 60 秒再点；页面本身对错误有 toast 提示，属正常业务限制。
- **预防**：把「接口频控」写进自测清单，联调阶段准备 3 个以上测试手机号轮换。

### 问题 5：整页截图里底部固定栏跑到内容中间

- **现象**：详情页用 `captureBeyondViewport` 整页截图时，「立即报名」固定底栏出现在活动介绍中间，像布局错乱。
- **原因**：`position: fixed` 元素相对视口定位，整页截图把视口拉长后它仍贴在原视口底部。
- **解决**：详情页改为按 750×1334 视口截图，不整页拉伸。
- **预防**：有固定底栏的页面一律视口截图；截图前滚动到要看的位置。

## 七、AI 协作记录

### 第 1 次：登录态持久化方案 —— **否决了 AI 的插件方案**

- **我提问**：后台和小程序都要「刷新后保持登录」，用 Pinia 怎么写最省事？
- **AI 建议**：安装 `pinia-plugin-persistedstate`，给 store 加 `persist: true` 即可，两端通用。
- **我的判断**：**不采纳**。该插件默认走 `localStorage`，小程序端没有这个对象，需要额外配置自定义 storage，还要多装一个依赖；而我们的持久化只有 token 和用户信息两个字段，直接在 store 里调 `uni.setStorageSync` / `localStorage` 更可控。
- **最终做法**：`admin/src/stores/user.ts` 与 `app/src/stores/user.ts` 各自封装 `saveLogin / updateUser / logout`，读写各自的持久层（后台 localStorage，小程序 uni storage），key 与请求层保持一致。
- **结果**：后台刷新、小程序重启后仍是登录态（见截图 09、18），登出后持久层确实清空，没有出现「刷新复活」。

### 第 2 次：403 做成弹窗还是独立页面

- **我提问**：角色不匹配时怎么提示比较合适？
- **AI 建议**：用 `ElMessageBox.alert('无权限')` 弹一下再跳回首页，代码最少。
- **我的判断**：部分采纳但**改了形态**——作业明确要求「403/404 错误页」，弹窗不算页面，验收时截不出 403 页。改为独立路由 `/403`（`views/error/403.vue`），守卫里 `return { path: '/403' }`。
- **结果**：`#/403` 可直接访问也能被守卫跳转到，截图 07 即该页面。

### 第 3 次：活动卡片放首页还是各页各写

- **我提问**：首页「即将开始」和活动列表的卡片长得几乎一样，要不要复制一份？
- **AI 建议**：抽 `ActivityCard`，用 `showStatus` 之类的 props 控制差异，两处共用。
- **我的判断**：**采纳**。第一版首页自己写了一套卡片，列表页复用时发现样式要改两遍，改成组件后只维护一份。
- **结果**：`app/src/components/ActivityCard.vue` 被首页与列表页共用；后续调整分值角标只改一处，两个页面同时生效。
