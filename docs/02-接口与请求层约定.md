# 接口与请求层约定

## 1. 统一响应体

所有接口（含失败）都返回 HTTP 200 + 同一结构，前端只按 `code` 分支：

```json
{ "code": 0, "message": "ok", "data": { } }
```

- `code === 0`：成功，`data` 为业务数据；无返回内容的接口 `data` 为 `null`。
- `code !== 0`：业务失败，`message` 是可以直接展示给用户的中文提示。

错误码分段（后端 `ResultCode` 枚举，前后端共用同一套语义）：

| 段 | 含义 | 示例 |
| --- | --- | --- |
| 0 | 成功 | — |
| 10xxx | 认证与权限 | 10001 未登录或登录已过期 |
| 20xxx | 活动 | 20001 活动不存在 |
| 30xxx | 报名 | 30001 名额已满 |
| 40xxx | 签到 | 40001 签到码无效或已过期 |
| 50xxx | 通用 | 50001 参数错误、50000 系统繁忙 |
| 70xxx | 文件 | 70002 文件超过大小限制 |

只有两种例外情况走非 200 状态码：参数校验失败 400、未认证 401、无权限 403、文件超限 413，
它们同样返回上述结构体，前端拦截器统一处理。

## 2. 分页

```json
{ "code": 0, "message": "ok", "data": { "records": [], "total": 0, "page": 1, "size": 10 } }
```

前端类型统一为 `PageResult<T>`，字段名固定 `records / total / page / size`，
不出现 `list / rows / items` 之类的别名。

## 3. 请求层规则（两端一致）

1. **只写相对路径**：`/api/app/activities`。后端地址只存在于 `vite.config.ts` 的代理配置里，
   业务代码中不出现 `127.0.0.1:8016`（小程序端编译非 H5 平台时由 `request.ts` 统一补全地址）。
2. **拆包在拦截器里做**：调用方拿到的是 `data`，不是 `{ code, message, data }`。
3. **错误集中处理**：`code !== 0` 弹提示并 reject；401 清 token 并跳登录；403 提示无权限；
   网络失败提示"请检查后端是否启动"。页面里不再逐个写 `if (res.code !== 0)`。
4. **登录态**：token 存 `localStorage`（后台）/ `uni.setStorageSync`（小程序），
   请求头统一 `Authorization: Bearer <token>`。
5. **超时**：后台 15s；小程序走 `uni.request` 默认值，不额外设置。

## 4. 时间与数字

- 时间：字符串 `yyyy-MM-dd HH:mm:ss`，后端 Jackson 全局配置时区 `Asia/Shanghai`。
- 雪花 ID：19 位 `Long` 超出 JS `Number.MAX_SAFE_INTEGER`，后端统一把 `Long` 序列化为字符串，
  前端类型里 ID 用 `number` 接收但**只做透传比较**，不做数值运算。
